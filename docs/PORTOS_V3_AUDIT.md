# PORTOS V3 audit (Gate 0)

Baseline: commit `a9414fc` (PORTOS V2 complete, 329 unit tests, 84 Playwright passes, M01–M20 PASS).
Evidence screenshots of the baseline: `docs/qa/v3-g0/{desktop,mobile}-*.png` at 1440×900 and 390×844.

## 1. Routes (unchanged by V3; every legacy link still redirects)

- Canonical: `/ops/earth`, `/ops/region/:regionId`, `/ops/country/:countryId`, `/ops/city/:cityId`, `/ops/port/:portId`, `/ops` (auto).
- Query (orthogonal state): `vessel | voyage | incident | route | hazard`, `panel`, `time`, `speed`, `mode`, `view` (3d/2d), `layers`, `kpi`.
- Legacy: `/operations`, `/region/:id`, `/port/:id`, `/vessel/:id`, `/voyage/:id`, `/incidents/:id`, `/corridors/:id`, `/weather/:id`, `/compare/:id`, `/replay/:id` → `legacyToOps` (`src/router/legacyRedirects.ts`).
- Roles: five demo users in `sample-data/users.json`, capability gating in `src/stores/session.ts` and the workflow store; role switcher in `UserMenu.vue`.
- V3 adds query keys only (`camera`, `slot`, `report`, `flow`), never new path segments, so deep links stay stable.

## 2. Renderer ownership

- One `WebGLRenderer` and canvas, owned by `EarthScene` (`src/map/earth/EarthScene.ts`), shared by every scene (D-032).
- `SpatialDirector` owns the frame loop, flights and the `SceneCache` (LRU 3); `InputRouter` owns pointer events.
- Scenes: `EarthGlobeScene` (globe, three-scope-map derived, GPL notice), `Region3DScene` (region / country / city / port variant, GPL notice), `PortTwinLayer` (Singapore, Genoa, Rotterdam procedural twins).
- Overlay: `MaritimeOverlay` (instanced vessel glyphs, LOD0–2 procedural ships from `src/map/vessels3d/`), DOM labels via `OverlayProjectionAdapter`.
- Handoff: `EarthGeographyBridge` + `HandoffStage` (focus, dive, reveal, settle), readiness-gated.
- 2D: `PortMap2D.vue` (MapLibre, OpenFreeMap tiles) for port and optional region scope; the globe keeps its context with the loop stopped.

## 3. Data schema (sample-data, generated by `scripts/generate_demo_data.py`)

- Core: `vessels` (500), `ports` (100), `voyages` (200), `positions`, `portCalls`, `berths`, `terminals`, `anchorages`, `events`, `incidents`, `evidence`, `routes`, `weatherHazards`, `regions`, `users`, `manifest`.
- V2 module (`sample-data/v2/`): `scenario`, `flagshipTracks`, `portLayouts`, `berthSchedule`.
- Missing for V3: cargo units, stowage plans, shipments, transfer events, yard slots, trade flows, typed terminal equipment.

## 7. Rollback

Every V3 surface sits behind a flag (`src/core/flags.ts`). `?v3=0` (session) or `VITE_V3=0` (build) restores the V2
presentation; each flag also switches alone (`?v3Glass=0`, `VITE_V3_PORT_TWIN=0`, …). Fixture additions live in
`sample-data/v3/` and are optional to the loader, so removing them leaves V2 behaviour intact.
